# Retro: tickets 247 to 301 (2026-11-19)

Made with Matt Pocock's `/retro` skill. Covers all work since the last retro (`docs/retro-2026-11-18.md`, merge `27cea87`, 2026-11-18 10:27Z): 35 merges, 26 closed tickets (247, 263, 278 to 300, 239, 240, with 286), laptop checks 74 to 87, and the 0.3.0 installer.
Sources: the report blocks in the 35 merge commit bodies (27 have a Waste line; the rest are check records). Most severe first.

## What worked

- No control byte reached master. The pre-push check from the last retro (item 1) held; the scripted edits that went wrong (item 1 below) were caught before the push.
- Every merge used a message file. No report names a failed `git merge -F` (last retro, item 2).
- No report names a laptop action without the user's written yes; the probes (291, 293, 282, 283) each name it.
- Reviewers found real bugs in nearly every code ticket: 6 to 21 findings each, nearly all fixed before merge.

## 1. Scripted edits still go wrong (applied)

**What happened:** 9 of the 27 reports with a Waste line name a scripted edit that failed or wrote the wrong thing: dropped backslashes (check 86, `fix/display-rounds-quiet-reset`), a control byte `\5` (282), a lone CR (288), CRLF line ends lost by shell appends (299, 300), a PowerShell wildcard (293), three failed tries at control bytes (278), and a missing import line (279, stopped as it should). One more (286) undid an uncommitted edit with `git checkout` of a file. All were caught before the push, but each cost a round trip.
Many threads scripted their edits to one long `PLAN.md` line, which they did not want to Read whole.

**Fix:** step 4 of the `stage` skill now says: for one long line, such as a ticket in `PLAN.md`, Read only that line (`offset` and `limit`), then Edit it.

## 2. Unclear laptop check steps (applied)

**What happened:** check 86 lost time on which Win + P mode and which Settings (Windows' or the app's) a step meant. Check 84 used a `notepad.exe` copy as the stand-in Razer program; on Windows 11 it ends at once, so the user had to be asked again.

**Fix:** step 8 of the `stage` skill now says: in each step name the exact app, window and mode, and use a stand-in program that keeps running (a `powershell.exe` copy that sleeps).

## 3. The first design missed a path (skipped)

**What happened:** 7 tickets needed a second design after the first review round: 263 (a click ended the charger wait), 281 (the wake's rate rule used outside a wake), 279 (the soak check armed at a wake), 287 (refilled the whole window), 293 (4 rounds to make the GPU stand-in err only hot), 298 (30 tests broke on a shared send path), 300 (a retry cap too low, found only on the laptop). Their workflow fixes all say the same: list the other callers and paths before the first design.

**Why skipped:** the reviewers caught each before merge, which is their job, and each proposal fits one ticket. The stage skill's step 2 already asks to check the plan against the code.

## 4. Late clippy fails (skipped)

**What happened:** 6 reports name clippy round trips (247, 282, 283, 287, 294, 301), 4 of them `struct_excessive_bools` or `fn_params_excessive_bools`. In 287 one commit went in with a clippy error.

**Why skipped:** the pre-push hook runs clippy, so none reached master. A thread can run `cargo clippy -p <crate>` early, as 294 proposed; that is a habit, not a rule change.
