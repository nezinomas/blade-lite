## 1. A BOM hid 12 merges from the plan check (applied)

**What happened:** 12 merge subjects in this window start with a UTF-8 BOM (bytes `EF BB BF`), from `3b8805d` to `ace501f` (2026-11-19 08:48Z to 11:43Z). The pre-push check that a `fix/` or `spike/` merge changes `docs/PLAN.md` matches `^Merge branch '...`, so it skipped all 12. Each of the 11 `fix/` and `spike/` ones did change `PLAN.md` (read with `git diff --name-only`), so nothing was missed this time. What wrote the BOM is not known; a PowerShell 5.1 file write is likely, not proven. The message files written with the Write tool since have none.

**Fix:**
- `.githooks/pre-push` strips a leading BOM from the subject before the match. Tried on `3b8805d` (now matches) and `ace501f` (`chore/`, still not matched).
- `.githooks/commit-msg` refuses a message that starts with a BOM (Git runs it for `git merge` too). Tried on a file with a BOM (refused) and one without (passes).

## 2. Scripted edits still go wrong (applied)

**What happened:** 9 of the 27 reports with a Waste line name a scripted edit that failed or wrote the wrong thing: dropped backslashes (check 86, `fix/display-rounds-quiet-reset`), a control byte `\5` (282), a lone CR in `PLAN.md` (288), CRLF line ends lost by shell appends to tests (299, 300), a PowerShell wildcard (293), three failed tries at control bytes (278), and a missing import line (279, stopped as it should). One more (286) undid an uncommitted edit with `git checkout` of a file. All were caught before the push, but each cost a round trip.
Why the threads scripted these edits, the reports don't say. A likely reason, not proven, is the long lines in `PLAN.md`: Grep shows them as "[Omitted long matching line]", so a thread can't quote the old text without reading more.

**Fix:** step 4 of the `stage` skill now says: for one long line, such as a ticket in `PLAN.md`, Read only that line (`offset` and `limit`), then Edit it. The shell appends to tests are already covered by that step's "Edit files with the Edit tool".
