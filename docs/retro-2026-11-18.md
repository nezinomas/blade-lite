## 1. Scripted edits put control bytes into code and docs (applied)

**What happened:** 38 of the 93 stage reports name a failed scripted edit (a Python or PowerShell script in a Bash heredoc). Most failed safely: the old text was not found, often because the working copy has CRLF line ends (`core.autocrlf=true`, `file` shows CRLF) and the script's anchor had LF. But 8 reports name a script that wrote a wrong byte: a backslash in `\b`, `\r` or a Windows path became a control byte in `PLAN.md`, a log string or a path (for example 2026-11-14 `fix/key-report-filter`, 2026-11-15 `fix/release-build-security`, 2026-11-18 `fix/preset-send`). The stage skill already said "Edit files with the Edit tool", and the last retro skipped a stricter rule (its item 7). Many reports proposed the same fix again.
A new check over the tree found 3 such bytes still in master, all in test data (ticket 278).

**Fix:**
- The pre-push hook now refuses control bytes (all but tab, LF and CR) in the files a push changes. Tried on `de1f4c0` (finds the byte in `registry.rs`) and on today's master (finds none in the changed files).
- Step 4 of the `stage` skill now gives the reason for the Edit tool: it keeps the CRLF line ends and every backslash, and heredoc scripts lose both.
- Ticket 278 fixes the 3 bytes in `crates/platform/src/registry.rs` and `crates/razer-device/src/hid.rs`.

## 2. `git merge -F -` failed in 22 merges (applied)

**What happened:** step 11 of the `stage` skill says to put the report block in the merge commit's body. 22 reports name a failed merge: the thread gave the message on stdin with `git merge --no-ff <branch> -F - <<'EOF'`. Git 2.53 on the laptop answers `error: could not read file '-'` (exit 129; tried in a scratch repo, where `-F <file>` works). Each thread then found the file way itself. In 2 logs (252, the 253 to 262 batch) the push and branch delete on the next line ran after the failed merge; the push said "Everything up-to-date" and the delete refused, so nothing was lost.

**Fix:** step 10 of the `stage` skill now says: write the message to `target/merge-msg.txt` with the Write tool, then `git merge --no-ff <branch> -F target/merge-msg.txt`.
