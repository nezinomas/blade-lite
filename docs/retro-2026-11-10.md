## What worked

## 1. The check app blocked the push, and once it was an old build (applied)

**What happened:** laptop checks start the app with `cargo run -p blade-lite`, which runs `target\debug\blade-lite.exe`. The user leaves it running. The pre-push checks rebuild that exe, and Windows refuses ("Access is denied"). The push failed in tickets 67 and 79, and ticket 85 had to ask the user to quit before the push. Each cost a round trip to the user. In ticket 81 the user ran `target\release\blade-lite.exe`, built before the fix, so the check failed and was done again. Ticket 87 pointed the user at the same release exe.

**Fix:** `cargo app` (alias in `.cargo/config.toml`) runs the app from its own folder, `target/app`. `cargo t` and the push build only `target/debug`, so a running check app does not block them. `cargo app` always builds the checked-out code, so it is never an old build. `CLAUDE.md` ("Commands"), the `stage` skill (step 8) and `docs/window-check.md` now say to use it, and never a built exe.

**Why skipped:** a judgement call, not a pattern. One case is not enough for a rule.

## 4. No reading of the fans before the user acted (skipped)

**What happened:** in ticket 86 the user saw still fans on a hot laptop after killing the app. They changed the mode before anyone read the laptop, so the cause could not be proven.

**Why skipped:** the app was not running, so it can log nothing then. If it happens again, read the state (read only) before anything is changed.
