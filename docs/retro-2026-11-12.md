## 1. A laptop check could not pass: the check app died at sign-out (applied)

**What happened:** laptop check 23 (sign out with a manual fan, ticket 142) failed. The user started the app with `cargo app`, as the rules said. `cargo run` puts the app in a job that ends it with cargo, and Windows ends cargo with its terminal at a sign-out. So the app died before it heard the session end, and the fans stayed loud. Ticket 142 itself was fine.

**Fix:**
- Ticket 166 added `tools/Start-CheckApp.ps1` and a `CLAUDE.md` line: a check that ends the Windows session starts the app with that script.
- The `stage` skill (step 8) now names the script beside `cargo app`.
- Check 4 (restart) now starts the app with the script and ticks "Start with Windows" first. That item saves the running exe's path, and on 2026-11-12 the Run key had no Blade Lite value. Check 31 (`--tray` start) ends no session and keeps `cargo app`.

## 2. A script test started the app and sent a preset (applied)

**What happened:** in ticket 166 the thread ran its new start script to test it. The script started the app, and the app sent the saved preset (Performance) to the laptop. The thread told the user after it happened.

**Fix:** `CLAUDE.md` (hardware safety) now says: never start the app to test a script or tool that starts it. Test only the script's guards. The user starts the app for the laptop check.

## 3. Two tickets got the number 123 (applied)

**What happened:** tickets 119 and 120 ran one after the other. Each filed a review finding as ticket 123. Ticket 120 took the number without reading the highest number in `PLAN.md`, though step 7 of the `stage` skill says to. Ticket 121's thread found it later and renumbered one to 124 (`7eaeab1`).

**Fix:** the pre-push hook refuses a push when a ticket number shows twice across `docs/PLAN.md` and `docs/PLAN-done.md`. Tested on `4a49bb4` (finds 123) and on today's plan (finds none).

## 4. `PLAN.md` got Windows line ends (applied)

**What happened:** in the 129 to 135 batch, commit `f03a4d5` stored 78 lines of `docs/PLAN.md` with CRLF (the Windows line end). The diff showed 155 changed lines for a few real ones. The thread fixed it with a second commit (`149bb57`). Git on the laptop converts line ends only when it is sure a file is text, and `.gitattributes` covered only `.githooks/`.

**Fix:** `.gitattributes` now has `* text=auto`. Git stores every text file with LF, whatever the editor wrote. `.gitignore` was the one file stored with CRLF, and it is now LF.

## 5. The readiness batch report had no per-ticket lines (applied)

**What happened:** the batch of 21 tickets ended with one report: totals for time and tokens, and no Time, Waste or Workflow fix line per ticket. So this retro had little per-ticket data for the largest batch so far.

**Fix:** step 11 of the `stage` skill now also puts each stage's report block in the body of its merge commit, so `git log` keeps it.

## 6. Ticket merges with `test/` names skip the plan check (applied)

**What happened:** tickets 103 and 146 used `test/` branches, and 150 and 151 used `docs/` branches. The pre-push hook checks the plan tick only for `feature/`, `fix/` and `spike/` merges. All four did tick `PLAN.md`, so nothing was lost.

**Fix:** the hook now also checks `test/` and `refactor/` merges, and the old "Merge fix/..." form. `docs/` and `chore/` merges stay unchecked: most of them are not tickets.

## 7. Scripted edits instead of the Edit tool (skipped)

The 129 to 135 batch made 101 scripted edits and 71 Edit calls; 11 of the scripts failed (a PowerShell string not found, a broken `//!` line, code put inside a struct). **Why skipped:** each failure cost one tool call, and the scripts that must find their old text worked. Item 4 removes the worst harm (line ends). A stricter rule would likely be ignored like this one.
