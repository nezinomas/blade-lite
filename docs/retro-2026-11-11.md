## 1. A push ran its checks over another thread's unfinished work (applied)

**What happened:** tickets 75 and 77 ran in the same folder. 77 waited until 75 was merged and `master` was clean, then started to edit. But 75 had not pushed yet. Its pre-push checks then built 77's half-done files, and 75 stopped its push. The push went up later with 77. Other threads (97 to 100, 101 and the charge-limit test, 110 and 62) also waited on each other in the same folder.

**Fix:**
- The pre-push hook refuses a push when the folder has changes or new files that are not committed, or when the pushed commit is not the one checked out. The checks then always test only what is pushed. A branch delete is not checked.
- The `stage` skill (step 3) also calls the folder busy when `master` has commits `origin/master` lacks (`git rev-list --count origin/master..master`): a merge waits for its push. The user is shown what waits and told to wait for the thread or push it.
- The user now starts a fresh thread for each ticket (2026-11-10).

## 2. Token numbers missing from the stage report (applied)

**What happened:** the `get_usage` tool is deferred: it shows only by name until it is loaded. Threads read "if the tool is there" as "not there" and left the numbers out or wrote "not available" (tickets 89 and 90, the start of the 104 batch, and 76). Ticket 96 proposed the fix, and the coordinator then put it in each brief by hand.

**Fix:** the `stage` skill (step 1) now says to load `get_usage` with ToolSearch when it is deferred.
